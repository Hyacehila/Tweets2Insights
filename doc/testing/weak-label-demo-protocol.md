# LLM 弱标注 Demo 验证协议

协议版本：demo-v1。评测设计与评分工具已完成，下一步建立人工金标准并运行模型评测。

## 评测用途

正式项目使用模型弱标注，标注完成后自动进入分析。人工标签仅用于独立 Demo 评测。
正常运行仍执行自动格式与词库校验、字段级置信度判定、拒判、调用失败记录、预算控制和版本追溯。
缺失、拒判、失败和中性分别保存，联合统计仅使用所需字段有效的记录。

Demo 针对 Jev 或其他候选决策模型的特定方案版本评估质量。新事件的先导检索与 schema 冻结由程序自动执行。

## 样本与目标阈值

| 项目 | Demo 验收要求 |
|---|---|
| 人工金标准 | 共 600 条；校准集 200 条，独立测试集 400 条 |
| 目标字段 | 主题、发布者、情绪、情感极性、与 target_id 绑定的立场 |
| 分类质量 | 每个目标字段 macro-F1 ≥ 0.80 |
| 有效覆盖率 | 每个目标字段 ≥ 85% |
| 相对基线 | 同标签通用模型基线 macro-F1 减候选方案 macro-F1 ≤ 0.03，逐字段判断 |

样本按事件／时间分组划分；同帖、近重复及同一内容的图文版本必须位于同一集合。
两部分的具体事件、时间段、样本 ID、抽样种子和去重规则在模型调用前固化。
200 条用于阈值校准；400 条独立测试集不用于调整提示词、模型选择或拒判阈值。
标注人员依据相同标签定义独立给出人工真值。

## 指标计算口径

单标签字段按冻结 schema 中的类别计算 macro-F1；若情绪字段最终采用多标签，按冻结情绪词表
逐标签计算 F1 后取宏平均，并在 Demo 清单写明任务类型。类别集合与零分母处理规则在评分前固定。
情感极性按冻结的离散标签评分，连续编码用于展示和数值建模。

字段有效覆盖率为该字段 accepted 数除以测试集全部记录数；missing、abstained、failed 都计入分母。
用于门槛判断的质量指标在该字段 accepted 子集上计算，同时报告样本数、每类覆盖率及全测试集
端到端指标（把拒判／缺失／失败视为未正确输出）。
某字段没有有效输出或缺少可计算的真值时，结果为“无法评估”。

候选模型与同标签通用模型使用相同数据划分、标签定义和各自预先固定的配置。
分别报告两者的质量与覆盖率；在共同 accepted 子集上补充配对比较，显示拒判选择的影响。
默认基线不拒判；若启用基线拒判，需在看独立测试结果前登记规则，并单列覆盖率差异。
基线必须覆盖所有独立测试记录并提供各字段的明确状态；任何 missing/failed 均使该字段无法通过验收。
abstained 按预先登记的规则单列报告，缺失输出保留 missing 状态。数值比较使用 1e-12 容差处理浮点边界误差。
基线需覆盖相同的五个目标字段，含与 target_id 绑定的立场。

## 保存的 Demo 证据

保存数据划分与指纹、人工标签、schema/target 定义、provider/model/prompt 版本、阈值、逐条预测、
字段状态、混淆矩阵、macro-F1、覆盖率、调用量和费用。分别记录旧六轮成本与同标签基线成本。
节费目标为 50%–70%，按实际调用量、费用和基线成本单独评估。

验收结论记录“此版本弱标注方案在该 Demo 数据上通过／未通过”，附实际结果。
正式运行保存自动标注及其版本、拒判和用量记录。

## 评分入口

`opinion_core.evaluation.demo.evaluate_demo` 与同名模块 CLI 已实现首版单标签评分，包括主情绪单选。
固定类别集合计算 macro-F1，零分母记 0；accepted 子集为空时质量值为 null。
输出逐字段 accepted 子集 F1、全测试集 F1、覆盖率、每类覆盖、混淆矩阵、状态计数、基线差值、共同 accepted 子集比较。
样本规模不为 200/400 时可以输出诊断指标，但整体 passed 必为 false。空金标准、重复 ID、分组跨集合、
非法标签及立场 target_id 不匹配直接拒绝，不自动修正真值。

输入格式：gold.json 为记录列表，每条含 post_id、group_id、target_id、split（calibration/test）、
labels（topic/publisher/emotion/sentiment/stance 五字段）；candidate.json 与 baseline.json 为独立测试集
AnnotationRecord 列表，或包含 annotations 的标注结果文件。vocabulary.json 为各字段固定类别列表。
准备数据时按事件/时间、重复帖及图文版本分组；评分程序根据 group_id 检查集合间分组泄漏。

```powershell
uv run python -m opinion_core.evaluation.demo --gold gold.json --candidate candidate.json --baseline baseline.json --vocabulary vocabulary.json --output demo-evaluation.json
```

输出包含输入 SHA256 与协议版本；返回码 0 表示全部条件通过，2 表示未通过。
评分命令离线读取准备好的人工标签与模型预测。评测进度见[实施记录](../upgrade-status.md)。
